# 国内上线备忘录（重建/迁移清单）

> 用途：当前产品跑在 **Vercel（海外）+ Neon（海外）+ Vercel Blob（海外存储）+ Qwen/DeepSeek** 上。
> 本次「账号诊断」已确认一个关键约束：**阿里云千问（DashScope）从 Vercel 的 `*.blob.vercel-storage.com` 跨云下载视频会超时**
> （实测 `HTTP 400 Download multimodal file timed out`），导致「AI 看视频」失败。
> **国内上线时必须把视频存储迁到阿里云 OSS**（DashScope 拉 OSS 内网直达），否则大视频诊断无法工作。
>
> 准备国内上线前，按本清单逐项核对；许多是**基础设施/资源项**（需你开通、给凭据），部分要**改代码**（我这边做）。

---

## 一、必须先解决的架构根源

### 1. 存储：Vercel Blob → 阿里云 OSS（最高优先，直接决定诊断/分析能否用）

- **现状**：视频/截图直传 Vercel Blob（`BLOB_READ_WRITE_TOKEN`，store `61evkmjcnpuj2gcd`），Qwen 用公网 URL 拉取。
- **问题**：DashScope（阿里云）拉 Vercel 视频超时 → 视觉分析失败。
- **国内方案**：视频/截图存**阿里云 OSS**（或阿里云百炼同区 OSS），DashScope 内网/原生拉取，支持大视频（放开 50M/5 个的原设计）。
- **要改的代码**：
  - 用阿里云 OSS SDK 替换 `@vercel/blob` 直传（服务端签名 / STS 直传）。OSS 的 `client.upload` 上传后拿公网 URL。
  - 新增 OSS 配置：`OSS_REGION`、`OSS_BUCKET`、`OSS_ACCESS_KEY_ID`、`OSS_ACCESS_KEY_SECRET`（或 STS）。
  - `app/api/blob/upload/route.ts`、`lib/upload.ts`、`app/diagnosis/page.tsx`、`app/analyze/page.tsx`、`app/clinic/page.tsx` 里的 Blob 直传逻辑全部换成 OSS。可保留「方案 B 小视频 data URL」作降级兜底。
- **需你提供**：阿里云 OSS bucket + AK/SK（建议子账号保密桶 + 最小权限）。

### 2. 过渡方案 B（已在代码中，落地前可保持）

- 视频 ≤ **2.5MB** 时，前端把视频读成 **base64 data URL**，直接交给千问（`{ type:"video", video: dataUrl }`），**绕开跨云下载超时**。
- 大视频仍走 Blob URL（当前会因跨云超时失败）。国内上线用 OSS 后放开大视频。
- 边界：依赖 Vercel 函数 **4.5MB 请求体限制**（base64 后约 3.3MB），所以只适合小视频。
